The problem

A cheap parcel can become a billion-dollar mistake.

Real estate teams, energy consultants, engineers and analysts study the same project with different data and different assumptions. The same five problems keep coming back.

A

Land is not power

Land is bought before electricity is secured. Capital sits idle, grid upgrades get expensive and energization dates slip.

B

Cost-first ignores lifecycle

The cheapest acquisition is rarely the best investment once interconnection, cooling, tariffs and delay are counted.

C

Fragmented diligence

Separate teams, datasets and assumptions slow decisions down and hide the tradeoffs between them.

D

Grid stress

Large loads raise peaks. AI training and batch work could ease off when the grid is strained, but planning models ignore it.

E

Community cost

Water, noise, nearby homes and diesel backup are treated as afterthoughts instead of hard limits.

The big idea

Put operations into the site decision, before capital is committed.

Most teams pick land, then chase power, then plan operations. Each step limits the next. SiteStar evaluates all three in one optimizer, so the site you pick is affordable to build, possible to power and efficient to run.

What's new, honestly stated. Carbon-aware scheduling, property analytics and grid flexibility each already exist. Our contribution is combining them in the site-acquisition decision, with a visible cost-first baseline to beat.

How it works

Three questions, answered together.

Where to build

Search real commercial parcels, then apply pass/fail gates for nearby homes, water stress, flood exposure and zoning.

When power can arrive

Estimate grid feasibility and time to power, then model CAPEX, OPEX, NPV, payback and the cost of every month of delay.

How to run it

Choose cooling, flexibility level and an hourly workload schedule that respects deadlines, prices and grid conditions.

The analyst's workflow

  1. CreateCapacity, region, land budget, target date, workload mix
  2. DiscoverAgent returns a shortlist of real parcels with sources
  3. ScreenEach parcel is Pass, Fail or Needs review, with reasons
  4. OptimizeSite, cooling, flexibility and schedule solved jointly
  5. InvestigateChange price, water or delay and see why the answer moved
  6. ExportRecommendation with financials, risks and evidence trail

Core modules

Five modules, one decision.

01

Site Intelligence

Real CoStar parcels, Vexcel aerial imagery and hard screens for homes, water, flood and cooling compatibility.

02

PowerReady

Preliminary grid feasibility, time-to-power scenarios and a transparent investment model: CAPEX, OPEX, NPV, payback, cost of delay.

Actual grid capacity and connection dates require utility confirmation.

03

Flex-to-Connect

An optimizer that picks site, cooling, flexibility and hourly schedule together, then compares the result with a cost-first plan on the same feasible parcels.

04

AI Intelligence

An agent on Claude that researches, calls the optimizer, runs what-ifs and drafts reports. It explains the numbers; it never invents them.

05

Live Digital Twin

Real machines run the same workload under baseline and optimized schedules with measured watts. An ESP32 miniature grid replays a real ERCOT day, and a Tello EDU drone gives a live aerial view of the model site.

Principles

Rules the product won't break.

Hard gates, not blended scores

A site over the water limit or too close to homes is rejected, even if it is the cheapest. A good financial score can't buy it back.

The optimizer decides, the AI explains

The language model calls tools and writes the explanation. It never generates site scores, prices, capacity or results.

Beat a realistic baseline

We compare against the cheapest site that passes the same gates, not against an obviously bad one.

Report what the data shows

If real parcels rank differently than our storyline, we show the real ranking. Attributes are never edited.

How to run the live feeds
  1. Install the bridge: pip install -r bridge/requirements.txt
  2. No hardware yet? python bridge/server.py --mock simulates both feeds.
  3. Drone, simple setup: join the drone's TELLO-XXXXXX Wi-Fi, then python bridge/server.py.
  4. Drone and internet at the same time: run python bridge/tello_wifi.py <router-ssid> once, then python bridge/server.py --tello-ip <drone-ip>.
  5. Workload machines push watts to POST /api/grid/telemetry and read GET /api/grid to learn about grid events.

Honest limits

Every number says where it came from.

Each figure in SiteStar carries one of five labels, and clicking it shows the source, timestamp and formula behind it.

Measured
Read from our own sensors: device watts, workload duration, completion, response time.
Sourced
From a named dataset with a timestamp: CoStar price, ERCOT price, WRI water stress.
Estimated
Derived by a documented method: distance to homes, CO₂, modeled cost.
Simulated
Scenario or replay: miniature grid, diesel indicator, results scaled to 100 MW.
Utility-confirmed
From a utility study. We expect this to be empty during the hackathon.
  • A nearby substation is not available grid capacity.
  • ERCOT wholesale prices are not a customer's contracted rate.
  • Annual emissions factors are not hourly carbon measurements.
  • Hardware shows how a workload responds. It does not prove a 100 MW site's interconnection or lower household bills.
